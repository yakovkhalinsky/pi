# pi setup backup

Portable backup of the [`pi`](https://github.com/earendil-works/pi-coding-agent)
coding-agent setup that lives under `~/.pi/`. This lets you recreate the same
configuration on another macOS/Linux machine from a clean clone.

## What's backed up (portable config only)

| Path | What |
|------|------|
| `bin/pi` | Wrapper shim that execs pi on its own bundled Node (`~/.pi/node`). |
| `agent/agents/` | ATP role definitions (archivist, builder, dispatcher, researcher, router, runtime, verifier). |
| `agent/prompts/` | Team prompt templates (team-charter, team-continue, team-escalate, team-handoff, team-status, team). |
| `agent/extensions/` | Extension source (agentic-team-protocol, web-search-pretty). |
| `agent/skills/` | Skills (agentic-team-protocol: README, CHARTER, SKILL, eden.sh). |
| `agent/settings.json` | Safe prefs only (theme, defaultModel, defaultProvider, compaction, packages) — **no secrets**. |
| `agent/models.example.json` | Sanitized provider/model template with `apiKey: ""`. `install.sh` copies it to `~/.pi/agent/models.json` only if the target doesn't already exist. |
| `agent/npm/.gitignore` | Self-ignoring marker for the npm extension cache (node_modules and the lockfile are regenerated, never committed). |
| `agent/npm/package.json` | Pinned extension manifest: exact versions of `pi-submarine`, `@heyhuynhgiabuu/pi-pretty`, `@heyhuynhgiabuu/pi-diff`, `@ollama/pi-web-search`, a `diff` security override (CVE-2026-24001), and the `allowScripts` install-script policy. |
| `install.sh` | Idempotent installer that recreates `~/.pi` from this directory. |

## What's deliberately NOT backed up

| Excluded | Why |
|----------|-----|
| `~/.pi/node/` (319M) | Bundled Node v24.19.0 + the pi npm package — re-downloadable; `install.sh` fetches it. |
| `agent/sessions/` | Full conversation transcripts — sensitive. |
| `agent/auth.json` | Auth token store (secret). `install.sh` recreates an empty `{}` placeholder. |
| `agent/models-store.json` | Provider credential store (secret). `install.sh` recreates an empty `{}` placeholder. |
| `agent/models.json` (unsanitized) | Contains real `apiKey`. Only the sanitized `models.example.json` template is committed. |
| `agent/npm/node_modules/`, `package-lock.json` | npm cache — regenerated by `install.sh`. |

See `.gitignore` for the exact ignore rules.

## Keeping this repo public-safe

This repo is public — every commit is world-visible. Before committing, run
`sh scripts/check-public-safe.sh` (staged files) or with `--all` (whole
tree); it blocks secret file names, credential values, personal absolute
paths, and identifier leaks. It also runs in CI on every push, and locally
as the pre-commit hook once you've run:

```sh
git config core.hooksPath .githooks
```

`AGENTS.md` carries the same rules for agent sessions working in this repo.

## Recreate on a new machine

```sh
git clone git@github.com:yakovkhalinsky/pi.git
cd pi
./install.sh
# start a new shell (so $PATH picks up ~/.pi/bin), then:
pi            # or: pi login
```

`install.sh` is idempotent and safe to re-run. It never overwrites existing
secrets (`auth.json`, `models-store.json`, `models.json`) or existing config
directories — it only fills in what's missing. Re-running it on an existing
install is safe: if `~/.pi/node` is already at the pinned version it skips the
download, and if the version has changed it downloads the new Node into a
staging directory, verifies it runs, and atomically swaps it into place — so
`~/.pi/node` is never left with a mix of old and new version files.

### What `install.sh` does

1. Downloads Node v24.19.0 for your `uname -m`/`uname -s` into a staging dir, verifies it runs and reports the pinned version, then atomically swaps it into `~/.pi/node/`. Skips the download if `~/.pi/node` is already at that version; a version change cleanly replaces (never merges) the old Node.
2. `npm install -g @earendil-works/pi-coding-agent@0.85.1` into `~/.pi/node` (pinned version — skips if already installed).
3. Installs the `bin/pi` wrapper shim to `~/.pi/bin/pi`.
4. Copies `agents/`, `prompts/`, `extensions/`, `skills/` to `~/.pi/agent/` (only if missing).
5. Copies `settings.json` to `~/.pi/agent/` (only if missing), then pins the extension package specs in `packages` to the manifest versions (existing entries only — nothing added or removed).
6. Copies the sanitized `models.example.json` to `~/.pi/agent/models.json` (only if missing — you then fill in the real `apiKey`).
7. Ensures empty `auth.json` / `models-store.json` placeholders exist (`{}`).
8. Merges the pinned extension manifest (exact versions, `diff` security override, `allowScripts` policy) into `~/.pi/agent/npm/package.json`, then runs `npm install` there to reconcile `node_modules`.
9. Runs `pi update --extensions` to reconcile installed packages (pinned specs are skipped by design — nothing floats to latest).
10. Appends `export PATH="$HOME/.pi/bin:$PATH"` to `~/.zshrc` once and checks the eden-memory (ATP) identity config.

## Updating this backup

The source of truth is `~/.pi/`. To refresh the backup (read-only on the
source — copy out, never modify `~/.pi/`):

```sh
# from the repo root:
cp -R ~/.pi/agent/agents    agent/agents
cp -R ~/.pi/agent/prompts   agent/prompts
cp -R ~/.pi/agent/extensions agent/extensions
cp -R ~/.pi/agent/skills    agent/skills
cp ~/.pi/agent/settings.json     agent/settings.json
cp ~/.pi/agent/npm/package.json  agent/npm/package.json
cp ~/.pi/bin/pi              bin/pi
# re-sanitize models.json → pi/agent/models.example.json (set apiKey: "")
git add agent/ bin/ install.sh
git commit -m "Update pi setup backup"
git push origin main
```

Never copy `auth.json`, `models-store.json`, `sessions/`, `node/`, or the
unsanitized `models.json` into this directory — they're git-ignored, but
double-check before committing.
